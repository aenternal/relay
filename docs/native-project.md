# Перенос проектов

Native project — один UTF-8 JSON-документ `relay-project`, версия `1`. Экспорт выбирает одно рабочее пространство. Импорт создаёт новое пространство; существующие запросы, настройки и открытые вкладки сохраняются.

```json
{
  "format": "relay-project",
  "version": 1,
  "workspace": {"id": "transfer-id", "name": "Example", "activeEnvironmentId": ""},
  "collections": [],
  "folders": [],
  "requests": [],
  "environments": [],
  "schemas": []
}
```

Коллекции, папки, HTTP/gRPC/WebSocket definitions и окружения используют обычные модели приложения. Внешний формат не содержит `State`, revision, UI, историю ответов или настройки приложения. Экспорт выдаёт новые идентификаторы переноса, а импорт повторно заменяет все идентификаторы сущностей и внутренние ссылки: родителя папки, коллекцию запроса, активное окружение и выбранную gRPC-схему. Ссылка за пределы импортируемого проекта или повторяющийся ID отклоняет весь импорт.

Каждый элемент `schemas` содержит `metadata` и `descriptorSetBase64`. Metadata — `id`, `workspaceId`, `name`, `kind`, SHA-256 `checksum`, RFC3339 `importedAt`, `rootFiles` и `files`. `descriptorSetBase64` содержит бинарный самодостаточный `FileDescriptorSet`; исходные физические пути и include directories для восстановления не требуются. При импорте приложение проверяет checksum, виртуальные имена файлов, корни и полный набор файлов, затем восстанавливает registry офлайн через тот же bounded Protobuf importer, который используется редактором схем. Неизвестные properties и версии native-документа отклоняются.

По умолчанию тела HTTP/gRPC/WebSocket, значения form/multipart и флаг их сохранения исключаются. Включение тел — отдельный явный выбор при экспорте и при импорте. Сохраняются только тела сохранённых definitions; несохранённые черновики не входят в экспорт. Включение тел не разрешает экспорт распознанных секретов.

Secret variables сохраняются как объявления с `secret: true`, пустыми `value` и `secretRef`. Значения публичных переменных с чувствительными именами, например `apiToken` или `password`, также исключаются и становятся пустыми secret declarations. Значения системного хранилища приложение при переносе не читает, не изменяет и не удаляет. Секреты после импорта нужно ввести заново.

Ссылки вида `{{token}}` в auth, headers, metadata и query сохраняются. Literal credentials из auth, Cookie/Authorization, чувствительных headers/query и URL userinfo очищаются с предупреждением. Известные значения этих credentials, keyring references и их URL/base64/hex представления удаляются также из остальных переносимых текстовых полей, включая явно включённые тела. Если исходный descriptor artifact содержит известное credential или его URL/base64/hex копию, например в комментарии, перенос отклоняется: бинарная схема не переписывается скрытно. Неизвестные значения обычных публичных переменных считаются публичными; пользователь задаёт secret type явно.

Файловые grants, имена локальных multipart-файлов и ссылки на CA/client certificate/private key всегда удаляются. После импорта файлы требуется выбрать через native dialog заново. URL, TLS server name, переключатель insecure, proxy mode, protocol options и временные ограничения сохраняются. Для произвольных текстовых тел пользователь сам выбирает включение и проверяет содержимое перед передачей файла.

Предпросмотр возвращает только название пространства, количество сущностей и ограниченный отчёт; он не изменяет SQLite. Apply повторно разбирает исходный документ, проверяет граф владения, создаёт новые IDs и добавляет данные к актуальной ревизии. Все definitions и descriptor artifacts сохраняются одной CAS-транзакцией SQLite. Ошибка descriptor, ownership, ревизии или записи откатывает изменение целиком. Успех импорта не активирует сеть и не отправляет сохранённые запросы.

Ограничения: документ до 32 MiB, JSON depth до 32, до 200 000 tokens, до 10 000 сущностей с учётом переменных, до 2 000 запросов, до 64 схем. Descriptor artifact до 16 MiB с дополнительными лимитами Protobuf importer. Duplicate JSON keys отклоняются до typed decoding. Sanitizer допускает до 1 024 разных credential literals суммарным объёмом до 1 MiB. Отчёт содержит до 200 warnings. Экспорт, preview и apply разделяют бюджет двух параллельных offline tools и timeout 30 секунд.

Postman Collection v2.1 и Insomnia export v4 импортируются через отдельные parsers в этот же промежуточный Document и проходят ту же privacy policy, проверку графа и атомарный commit. Поддерживаемое подмножество описано в отчёте импортера. Scripts, hooks и flows не исполняются; внешний код, сетевые `$ref` и файлы по путям из импортируемого документа не загружаются.
